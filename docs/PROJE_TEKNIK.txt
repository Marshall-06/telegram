================================================================================
1. PROJE OZETI
================================================================================

Telegram bot uzerinden yatirimci yonetimi yapan, arka planda Node.js ile
calisan tasınabilir bir backend uygulamasidir.

Frontend  : Telegram bot (grammY) — TR / EN / RU
Backend   : Node.js + TypeScript
Veritabani: SQLite (yerel gelistirme) / PostgreSQL (sunucu - planli)
Odeme     : Trust Wallet (ana hesap, USDT / BEP20)

Trading / borsa islemleri bu projeden BAGIMSIZDIR. Backend sadece:
  - Kullanici bakiyesi
  - Yatirim talepleri
  - Cekim talepleri (manuel admin gonderimi)
  - Aylik sabit kar dagitimi
islevlerini yonetir.

Hukuki yapi proje sahibi tarafindan ustlenilir.

================================================================================
2. IS MANTIGI VE KARARLAR
================================================================================

2.1 Yatirim
  - Kullanici bot uzerinden tutar girer
  - Sistem benzersiz referans kodu uretir (DEP-...)
  - WebMoney entegrasyonu gelince fatura/odeme eslestirme eklenecek
  - Onaylanan yatirim ledger'a "deposit" kaydi olarak yazilir (henuz otomatik degil)

2.2 Cekim (MANUEL ADMIN MODELI)
  - Kullanici talep olusturur
  - Bakiye ANINDA dusulmez; tutar "bekleyen cekim" olarak rezerve edilir
  - Cekilebilir bakiye = toplam bakiye - bekleyen cekim toplami
  - Admin'e liste gelir (cuzdan numarasi + tutar)
  - Admin WebMoney'den MANUEL gonderim yapar
  - Admin /admin_cekim_tamam ID ile bakiyeyi dusurur
  - Cekimler belirli gunlerde toplu islenir (WITHDRAW_DAYS)

2.3 Kar dagitimi
  - AYLIK, SABIT oran (MONTHLY_PROFIT_RATE)
  - Piyasa performansina bagli degil
  - Her ayin 1'inde saat 09:00 otomatik calisir
  - Aktif kullanicinin bakiyesine oran uygulanir
  - Ayni ay icin tekrar dagitim yapilmaz

2.4 WebMoney
  - Detaylar henuz netlesmedi
  - Env placeholder: WM_WMID, WM_PURSE, WM_KEY_PATH
  - Planlanan arayuzler: X1 (fatura), X8 (gelen transfer), X2 (cekim - opsiyonel)

================================================================================
5. VERITABANI SEMASI
================================================================================

User
  id, telegramId (unique), username, firstName, lastName
  wmPurse          : WebMoney cuzdan (cekim icin)
  status           : active | (ileride: suspended)
  createdAt, updatedAt

Deposit
  id, userId, amount, currency (WMZ)
  wmInvoiceId      : WebMoney fatura ID (gelecek)
  reference        : Benzersiz referans (DEP-...)
  status           : pending | matched | cancelled
  matchedAt, createdAt

Withdrawal
  id, userId, amount, fee, currency
  wmPurseSnapshot  : Talep anindaki cuzdan
  wmTransferId     : Admin transfer referansi (opsiyonel, gelecek)
  status           : pending | completed | cancelled
  scheduledFor     : Planlanan cekim gunu
  adminNote        : Admin notu
  processedAt, createdAt

LedgerEntry (cift kayit mantigi - tek yonlu zincir)
  id, userId
  type             : deposit | withdrawal | profit | fee | adjustment
  amount           : Pozitif veya negatif
  balanceAfter     : Islem sonrasi bakiye
  referenceId      : Iliskili deposit/withdrawal ID
  note, createdAt

ProfitDistribution
  id, periodYear, periodMonth (unique birlikte)
  profitRate, totalDistributed, status, createdAt

AppConfig
  key, value, updatedAt (ileride dinamik ayarlar icin)

6. BAKIYE MANTIGI
================================================================================

Toplam bakiye:
  Ledger'daki son kaydin balanceAfter degeri
  Kayit yoksa 0

Bekleyen cekim:
  status=pending olan Withdrawal kayitlarinin amount toplami

Cekilebilir bakiye:
  toplam_bakiye - bekleyen_cekim_toplami

Ledger kurallari:
  - Her para hareketi yeni bir LedgerEntry olusturur
  - balanceAfter negatif olamaz (yetersiz bakiye hatasi)
  - Cekim talebi olusturmada ledger YAZILMAZ (sadece rezervasyon)
  - Admin cekim tamamlayinca ledger'a negatif withdrawal yazilir

7. YATIRIM AKISI
================================================================================

1. Kullanici /deposit veya "Yatirim" butonu
2. Minimum tutar kontrolu (MIN_DEPOSIT)
3. Deposit kaydi olusturulur (status: pending)
4. Referans kodu kullaniciya gosterilir
5. [GELECEK] WebMoney X1 fatura + X8 eslestirme
6. [GELECEK] Eslesince ledger deposit + status matched

Dosya: src/services/investment.service.ts -> createDepositRequest()

================================================================================
8. CEKIM AKISI
================================================================================

KULLANICI TARAFI:
1. /withdraw veya "Cekim" butonu
2. wmPurse yoksa cuzdan numarasi sorulur (format: Z + 12 rakam)
3. Tutar sorulur (MIN_WITHDRAW kontrolu)
4. Cekilebilir bakiye kontrolu
5. Withdrawal kaydi (pending) + scheduledFor hesaplanir
6. Kullaniciya planlanan gun bildirilir

ADMIN TARAFI:
1. WITHDRAW_DAYS gunlerinde saat WITHDRAW_NOTIFY_HOUR'da otomatik liste
   veya /admin_cekimler ile manuel liste
2. Admin WebMoney'den manuel transfer yapar
3. /admin_cekim_tamam ID  -> ledger dusum + status completed + kullanici bildirimi
4. /admin_cekim_iptal ID  -> status cancelled, bakiye degismez

Cekim gunu hesaplama:
  WITHDRAW_DAYS=1,15  -> ayin 1 ve 15'i
  Talep gununden itibaren ilk uygun gun scheduledFor olur

Dosyalar:
  src/services/withdrawal.service.ts
  src/bot/commands/admin.ts
  src/lib/withdraw-schedule.ts
  src/jobs/withdraw-notify.job.ts

================================================================================
9. AYLIK KAR DAGITIMI
================================================================================

Zamanlama : Her ayin 1'i, saat 09:00 (cron: "0 9 1 * *")
Oran      : MONTHLY_PROFIT_RATE (varsayilan %5)

Algoritma:
  1. Bu ay icin ProfitDistribution var mi kontrol et
  2. status=active kullanicilari getir
  3. Her kullanici icin guncel bakiye > 0 ise:
     kar = bakiye * (profitRate / 100)
  4. Ledger'a type=profit kaydi yaz
  5. ProfitDistribution ozet kaydi olustur

Dosya: src/services/investment.service.ts -> distributeMonthlyProfit()
Job  : src/jobs/monthly-profit.job.ts

12. AG / TELEGRAM ERISIMI
================================================================================

Durum (mevcut ag):
  - VPN OLMADAN api.telegram.org erisilemiyor
  - Kurumsal DNS api.telegram.org adresini 127.0.0.1'e yonlendiriyor
  - Telefon VPN + PdaNet kullanilsa bile PC'de Kerio Virtual Network aciksa
    DNS yine kurumsal sunucuya gider (control.gulzemin.local / 10.168.115.1)
  - Bu bir kod hatasi degil; ag seviyesinde DNS engeli

Telefon VPN + PdaNet senaryosu:
  1. Telefonda VPN acik
  2. PdaNet ile PC'ye internet paylas
  3. PC'de Kerio / kurumsal ag adaptoru KAPAT (onemli!)
  4. Sadece "PdaNet Broadband Connection" aktif kalsin
  5. ipconfig /flushdns
  6. npm run check:telegram  -> BASARILI olmali
  7. npm run dev

Alternatif DNS duzeltme (yonetici CMD):
  echo 149.154.166.110 api.telegram.org >> C:\Windows\System32\drivers\etc\hosts
  ipconfig /flushdns
  (Gecici cozum; Kerio kapali + PdaNet tercih edilir)

Yerel gelistirme:
  1. VPN'i ac
  2. npm run dev calistir
  3. @Vanguard5_bot uzerinden test et

Production (onerilen):
  - Botu dis agdaki VPS'te calistir (Hetzner, DigitalOcean, vb.)
  - VPS'te Telegram genelde aciktir, VPN gerekmez
  - docker-compose + PostgreSQL ile kalici calisma

Opsiyonel proxy (.env):
  TELEGRAM_PROXY=http://127.0.0.1:7890
  (VPN yerel proxy sagliyorsa kullanilir; sistem VPN yeterliyse gerekmez)
